# Migration: Bun → Node 24 + pnpm

Status: planning → executing per-phase (each phase reviewed before the next).
Branch: `eleith/migrate-to-node-pnpm` (big-bang on one branch, many small healthy commits).

## Locked decisions
- **Runtime/PM:** Node 24 (matches local 24.15), pnpm (managed by **mise**, replacing bun).
- **SQLite:** `node:sqlite` (`DatabaseSync`, built into the Node binary) + vendored `NodeSqliteDialect`
  (from luzzle `e0a054e`) at `src/lib/server/db/node-sqlite-dialect.ts`.
- **Password hashing:** `@node-rs/argon2` (napi prebuilds incl. musl; verifies Bun's argon2id PHC strings).
- **Tests:** Vitest (node env, plain config — no SvelteKit plugin; tests use relative imports).
- **CLI TS exec:** `tsx` (devDep).
- **Docker base:** `node:24-alpine` (no native compiler needed: node:sqlite built-in; @node-rs/argon2 has musl prebuilds, no install script).
- **Cutover:** big-bang branch; **CI:** skipped for now.

## Key facts that de-risk this
- Already on `@sveltejs/adapter-node` → prod start is just `node build/index.js`.
- No `$lib`/`$app`/`$env` in test-reachable server code → Vitest needs no SvelteKit resolution.
- Only native dep is `@node-rs/argon2` (prebuilt, no build script) → pnpm build-gate not triggered.
- `node:sqlite` on Node 24: available without a flag and no longer emits the ExperimentalWarning — no suppression needed.

## Fresh-look refinements (post-migration, removing bun-legacy bandaids)
- **Vitest config:** folded `test` into `vite.config.ts` via the `sveltekit()` plugin (provides `$lib`/`$app`/`$env`); deleted `vitest.config.ts` and its hand-rolled `$lib` alias; converted tests' relative `../../src/lib/...` imports to `$lib/...`. The root `tests/` dir is fine — the smell was the missing plugin + relative imports (a bun-test idiom).
- **Scripts:** `prepare` is now stock `svelte-kit sync` (dropped the `|| echo ''` hack); `schema.d.ts` is generated by `build`/`dev`/`check`.
- **Docker:** `corepack enable` instead of `npm install -g pnpm` (the `packageManager` pin is the single source of truth); installs use `--ignore-scripts` (so `prepare` doesn't run before source is copied); dev image sets a shared world-readable `COREPACK_HOME` so pnpm works under any host UID. **Still needs a real `docker build` to confirm** (no daemon in dev sandbox), especially the dev image running pnpm at runtime as an arbitrary UID.
